Cloudflare SSH

When these fields are needed

Most common case
If the backup already works with Connection mode = Cloudflare and the Cloudflare fields empty, leave them empty. They are not mandatory.
Cloudflare auth home on host
Use this only when the host already has a valid cloudflared login session and you want the container to reuse it. The value is normally the host home directory that contains .cloudflared, for example /home/android18. Using / is not the intended value; if blank works, prefer blank.
How to get the auth home
On the host machine, log in with cloudflared as you normally would. The resulting credentials usually live under ~/.cloudflared, so the field should be that user home, not the .cloudflared subdirectory itself.
Service token ID and secret
These are only for Cloudflare Access. They are not the SSH password. Use them only if the container must authenticate to Cloudflare without reusing an existing host session. They come from the Cloudflare Zero Trust dashboard where Access service tokens are created.
SSH user and SSH password
These are separate and are sent to the remote SSH server itself after the Cloudflare layer.
